# 목 API(MSW) 시드와 AI 고정 동작

근거: api.md 전체, scenarios.yaml 머리 주석, 학생 답(2026-10-30: 시드는 E4 줄거리를 취준생의 실제 프로젝트 활동으로 옮긴 한 세트).
목 API는 개발 서버에서만 켜진다(`VITE_API_MOCK=false`면 끔). 배포 빌드에서는 실제 서버를 부른다.
같은 시드를 서버의 docker 첫 기동 시드에도 쓴다(백엔드가 이 파일을 따른다).

## 줄거리

컴퓨터공학과 4학년 2학기 취준생. 팀 프로젝트는 여러 번 했지만 기록을 남기지 않았다(P1).
ChatGPT로 만든 자소서 초안을 거의 그대로 붙여넣었고, 그 안에 측정한 적 없는 "공지 확인율 40%", 실제로는 맡지 않은 "팀을 주도해" 같은 문장이 섞여 있다(E4의 "폐기율 15%"와 같은 구조).

## 시드

계정: `seeker@example.com` (비밀번호는 docker-compose.yml의 `SEED_USER_PASSWORD`).

### 이력서 (R2)

- 글(`text`):

```
컴퓨터공학과 4학년(2026년 2월 졸업 예정)
- 캡스톤디자인 「학과 공지 알림 앱」 (2025년 1학기, 4인 팀, 백엔드·공지 크롤러 담당)
- 교내 해커톤 「동아리 회비 정산 웹」 (2025년 여름, 5인 팀 팀장)
- 프로그래밍 동아리 운영진 (2024년, 스터디 일정 관리)
```

- 초안(`drafts`): `프로그래밍 동아리 운영진` · `2024년` 하나만 남아 있다(앞의 두 활동은 이미 경험 1·2로 확정됨). 영상에서 "확정 전 활동"을 보여 주는 용도.
- 경험 1·2의 `summary`는 위 글에서 해당 줄.

### 경험 1: `캡스톤디자인 학과 공지 알림 앱` · `2025년 1학기`

- 단서: 글 단서 `발표 자료 마지막 장: 팀원 4명 역할 분담표 — 나는 백엔드·공지 크롤러`
- 확정 사실(모두 `said`, `origin: conversation`):
  - 상황: `학과 공지가 홈페이지에만 올라와 학생들이 신청 마감을 자주 놓쳤다`
  - 역할: `4명 팀에서 백엔드와 공지 크롤러를 맡았다. 팀장은 다른 팀원이었다`
  - 행동: `공지 게시판을 10분마다 확인해 새 글이 올라오면 앱 푸시를 보내는 크롤러를 만들었다`
  - 결과: `학과 단톡방에 공유해 한 학기 동안 시험 운영했고, 공지를 놓쳤다는 말이 줄었다는 반응을 들었다. 사용자 수나 확인율은 따로 재지 않았다`
- 의의: 비어 있음
- 대화: AI 질문 4개와 답 4개(위 사실이 나온 대화). 마지막 줄은 의의를 묻는 AI 질문(답 없음).
- 항목 상태: 상황 `explained`, 역할 `explained`, 행동 `explained`, 결과 `needs_more`, 의의 `null`
- 후보 1개(`ai_unverified`, 항목 의의): `반복되는 불편을 자동화로 줄이는 데 관심이 생겼다`

### 경험 2: `교내 해커톤 동아리 회비 정산 웹` · `2025년 여름`

- 단서: 없음
- 확정 사실(모두 `said`, `origin: manual`):
  - 역할: `5명 팀의 팀장으로 기능 범위를 정하고 발표를 맡았다`
  - 행동: `회비 입금 내역을 엑셀로 받아 정산 화면에 올리는 기능을 직접 만들었다`
  - 결과: `48시간 안에 시연까지 마쳤지만 수상은 하지 못했다`
- 대화: 없음(S4가 여기서 대화를 시작한다)
- 항목 상태: 모두 `null`

### 자소서: `가나다소프트 백엔드 지원` (`kind: pasted`)

본문:

```
저는 캡스톤디자인에서 학과 공지 알림 앱을 개발하며 데이터 기반으로 문제를 해결했습니다. 공지 크롤러를 설계해 학생들의 공지 확인율을 40% 높였고, 팀을 주도해 일정 안에 배포를 마쳤습니다. 교내 해커톤에서는 팀장으로서 동아리 회비 정산 서비스를 기획해 수상권에 근접한 성과를 거두었습니다. 이러한 경험을 바탕으로 사용자의 불편을 데이터로 해결하는 백엔드 개발자가 되겠습니다.
```

점검 기록: 없음(S6이 여기서 점검을 시작한다).

### 작성한 자소서: `라라테크 백엔드 지원` (`kind: generated`)

영상과 문항별 작성·자소서 상세 화면 확인용(학생 답 2026-10-30, 와이어프레임 3번).

- 우대사항 `REST API 설계 경험, 협업 도구 사용 경험`, 인재상 `문제를 끝까지 파고드는 사람`
- 문항 1 `직무 관련 경험을 바탕으로 본인의 강점을 서술하시오`: 근거 카드 경험 1·2, 응답은 두 카드의 확정 사실만 이어 쓴 문단(와이어프레임 3번 글과 같게), `answerEdited: false`
- 문항 2 `협업 과정에서 갈등을 해결한 경험을 서술하시오`: 응답 없음(`answer: null`), 선택·추천 없음
- 점검 기록: 없음

## AI 고정 동작 (목 API 전용)

실제 서버에서는 AI가 정한다. 목 API는 영상·테스트가 늘 같게 나오도록 아래처럼 고정한다. AI를 부르는 목 경로는 응답 전에 800ms 기다린다.

### 경험 대화 (`conversation/start`, `conversation/answers`)

- 첫 질문: `이 경험에서 해결하려던 문제는 무엇이었나요?`
- 답할 때마다: 아직 `explained`가 아닌 첫 항목을 `explained`로 바꾸고, 그 다음 항목을 묻는 질문을 낸다(`그때 본인이 맡은 역할은 무엇이었나요?` → `구체적으로 어떤 행동을 했나요?` → `결과는 어땠나요? 직접 확인한 것만 말해 주세요.` → `이 경험이 지금 지원에 어떤 의미가 있나요?`).
- 답 글 전체를 그 항목의 후보 하나로 만든다(`ai_unverified`).

### 이력서 활동 나누기 (`POST /api/resume`)

- 줄마다 `- `로 시작하는 줄을 활동 하나로 본다. 「」 안을 제목에, 첫 괄호의 첫 부분을 시기에, 줄 전체를 `summary`에 넣는다. `- ` 줄이 없으면 빈 줄로 나눈 문단마다 하나.
- 이미 있는 경험·초안과 제목이 같은 활동은 뺀다.

### 카드 추천 (`recommendations`)

- 확정 사실이 있는 경험 모두를 추천한다. 이유: 문항에 `협업`·`팀`이 있으면 해커톤 카드에 `팀장으로 범위를 정한 경험이 문항과 맞아요`, 그 밖에는 캡스톤 카드에 `직접 만든 기능과 결과가 문항과 맞아요`.

### 문항 응답 (`answer`)

- 고른 카드의 확정 사실을 이어 붙여 한 문단으로 만든다. 카드에 없는 숫자는 넣지 않는다.

### 점검 문장 고르기 (`checks`)

시드 자소서에서 아래 네 문장을 이 순서로 고른다. 다른 자소서는 숫자·`주도`·`기반`·`성과`가 든 문장을 고른다.

| 문장                                                       | 첫 질문                                                              | 판정 대상 기준 |
| ---------------------------------------------------------- | -------------------------------------------------------------------- | -------------- |
| `…데이터 기반으로 문제를 해결했습니다.`                    | `여기서 '데이터 기반'은 어떤 데이터를 어떤 도구로 본 건가요?`        | J3, J4         |
| `공지 크롤러를 설계해 학생들의 공지 확인율을 40% 높였고,…` | `40%는 무엇과 비교해, 어느 기간에, 어떻게 잰 값인가요?`              | J1, J2, J4     |
| `…팀을 주도해 일정 안에 배포를 마쳤습니다.`                | `팀을 주도했다고 하셨는데, 팀에서 본인이 직접 한 일은 무엇이었나요?` | J2, J3         |
| `…수상권에 근접한 성과를 거두었습니다.`                    | `'수상권에 근접한 성과'는 실제로 어떤 결과였나요?`                   | J3, J4         |

### 점검 답 판정 (`answers`)

- 답에 `재지`, `모르`, `기억`, `없었`이 있으면 `unknown`으로 끝낸다(R11, 모름 판정을 먼저).
- 그 밖에 답이 40자 이상이면 판정 대상 기준을 모두 `met`으로 하고 `explained`.
- 40자 미만이면 첫 대상 기준을 `missing`으로 하고, 남은 추가 질문이 있으면 `조금 더 구체적으로, 직접 한 행동과 확인한 결과를 말해 주세요.`를 묻는다. 없으면 `needs_more`.
- 답 글 전체를 후보 하나로 만든다. 문장이 캡스톤·해커톤 중 어느 쪽 이야기인지 알 수 있으면 그 경험을 `experienceId`로 둔다(붙여넣은 자소서는 `null`도 된다).

### 실패 흉내

- 테스트에서는 MSW의 `server.use(...)`로 해당 AI 경로를 `502 { error: { code: "AI_UNAVAILABLE" } }`로 덮어써 실패를 흉내 낸다. 화면 코드에는 실패 흉내 장치를 넣지 않는다.
