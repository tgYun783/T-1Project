# 06 문항별 작성 (I) `/cover-letters/:id/items/:itemId`

근거: R8, R13, C1, C4, screen-spec.md 3절 I, api.md 7·8절. 시나리오: S5. 자소서 잠금 적용.

lilac 단계. 문항은 순서대로 하나씩 진행한다. 배치(학생 답 2026-10-30): 왼쪽 넓은 칸에 문항과 응답(큰 카드), 오른쪽 좁은 칸에 추천·선택 카드와 근거 카드를 세로로 쌓는다. 자세한 배치는 docs/design/wireframes/를 따른다.

## 위

- 문항 진행 막대: 전체 문항 칸, `answer`가 있는 문항은 채운 칸. 아래 한 줄 `응답 N / 문항 M`.
- 문항 번호 이동 `문항 1`, `문항 2`… (누르면 그 문항 주소로).
- 현재 문항 글.

## ① 추천

- 이 문항의 `recommendations`가 비어 있으면 들어올 때 `POST .../items/:itemId/recommendations`를 부른다(AI 호출 규칙).
- 제목 `추천 경험 카드`. 카드마다 경험 제목과 추천 이유.
- `400 NO_CONFIRMED_FACTS`면 `확정된 사실이 있는 경험 카드가 없어요.`와 보조 버튼 `경험으로 가기`.

## ② 카드 고르기

- 추천 카드와 제목 `다른 카드` 아래의 나머지 카드(확정 사실이 1개 이상인 경험)를 토글 버튼으로 켜고 끈다. 토글 버튼 이름은 경험 제목. `aria-pressed`로 상태 표시.
- 처음 켜진 카드는 이 문항의 `selectedExperienceIds`.
- 다른 문항의 `selectedExperienceIds`에 있는 카드에는 `문항 N에 사용 중`을 붙인다(화면에서 계산). 막지 않는다.
- 카드 옆 보조 버튼 `사실 보기`: 그 카드의 확정 사실을 펼친다. 펼친 곳에 보조 버튼 `이 카드 보강하기`(→ `/experiences/:id?returnTo=<현재 주소>`).

## ③ 만들기

- 주 버튼 `이 문항 만들기`. 켜진 카드가 없으면 잠근다.
- 누르면 `PUT .../items/:itemId/experiences`(켜진 카드) → `POST .../items/:itemId/answer`.
- 이미 응답이 있고 `answerEdited: true`면 먼저 확인창: `고친 내용이 새 응답으로 바뀌어요. 계속할까요?`, 버튼 `바꾸기` / `취소`. `바꾸기`면 `confirmOverwrite: true`로 보낸다. 서버가 `409 OVERWRITE_CONFIRM_REQUIRED`를 줘도 같은 확인창을 띄운다.
- AI가 알아서 다시 만들지 않는다. 이 버튼을 누를 때만 만든다(C4).

## 결과

- 입력칸 `응답`(고칠 수 있음), 보조 버튼 `응답 저장`(`PATCH .../items/:itemId`).
- `근거 경험 카드`: `usedExperienceIds`의 경험 제목.
- 보조 버튼 `다음 문항`(마지막 문항이면 `자소서 보기` → `/cover-letters/:id`).

## 테스트

- 들어오면 추천 카드와 이유가 보인다.
- 시드 카드 `캡스톤디자인 학과 공지 알림 앱`을 켜고 `이 문항 만들기` → `응답`과 `근거 경험 카드`에 그 제목이 보인다.
- 다른 문항에서 고른 카드에 `문항 1에 사용 중`이 보인다.
- 응답을 고쳐 저장한 뒤 `이 문항 만들기` → 확인창이 뜨고 `바꾸기`를 눌러야 바뀐다.
