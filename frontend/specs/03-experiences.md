# 03 경험 목록·이력서 입력 (D, E)

근거: R2, R6, screen-spec.md 3절 D·E, api.md 4절. 시나리오: S2, S4.
경험은 이력서의 활동을 확정해서만 만든다. 경험을 하나씩 따로 만드는 화면은 없다(R2, 학생 답 2026-10-30).

## D 경험 목록 `/experiences`

- lime 블록. 주 버튼 `이력서에서 활동 추가`(→ `/resume`).
- 목록: `GET /api/experiences`(최근 수정순). 행마다:
  - 제목, 시기
  - 다섯 항목 칸 `상황`·`역할`·`행동`·`결과`·`의의`: 그 항목에 확정 사실이 있으면 흰 칸, 없으면 점선 칸
  - 확인 대기 후보가 있으면 `확인 대기 N`
  - 행(제목)을 누르면 `/experiences/:id`.
- 비어 있으면 점선 행 `아직 경험이 없어요`와 보조 버튼 `이력서 입력`(→ `/resume`).

## E 이력서 입력 `/resume`

`GET /api/resume`.

### 이력서 붙여넣기

| 영역   | 화면 글자                                                                    |
| ------ | ---------------------------------------------------------------------------- |
| 입력칸 | `이력서`(여러 줄, 자리표시자 `이력서나 활동 목록을 그대로 붙여넣어 주세요`)  |
| 버튼   | `활동 나누기` → `POST /api/resume` (AI 호출 규칙 적용)                       |
| 안내   | 이미 붙여넣은 적이 있으면: `다시 붙여넣으면 새로 나온 활동만 목록에 더해요.` |

- 처음 들어오면 `이력서` 칸에 지난번 글(`resume.text`)을 채운다.
- `이력서`가 비면 `활동 나누기`를 잠근다.

### 활동 확인 (R2)

- 제목 `확인할 활동`. `drafts`마다 한 행: 활동 이름, 시기, 이력서에서 온 부분(`summary`) 한두 줄.
  - 버튼 `고치기` → 입력칸 `활동 이름`, `대략적 시기`, `한 줄 설명`과 버튼 `저장`(`PATCH /api/resume/drafts/:draftId`)
  - 버튼 `빼기` → `DELETE /api/resume/drafts/:draftId`
- 보조 버튼 `활동 직접 추가`: 입력칸 `활동 이름`(필수), `대략적 시기`, `한 줄 설명`과 버튼 `목록에 추가`(`POST /api/resume/drafts`). 이력서를 붙여넣지 않았거나 AI가 실패해도 쓸 수 있다.
- 주 버튼 `경험 만들기`: 목록의 모든 활동을 확정한다(`POST /api/resume/drafts/confirm`, `draftIds` = 지금 목록 전부). 성공하면 만든 경험 중 첫 번째의 `/experiences/:id`로 간다.
- 목록이 비면 점선 행 `확인할 활동이 없어요`, `경험 만들기`는 잠근다.
- 예외: `활동 이름`이 비면 `필수 입력이에요.`

## 테스트

- 이력서를 붙여넣고 `활동 나누기` → `확인할 활동`에 활동이 보인다.
- `활동 직접 추가`로 `활동 이름`·`대략적 시기`를 넣고 `목록에 추가` → `경험 만들기` → 경험 상세로 간다.
- AI 실패(502)면 `다시 시도`가 보이고 `활동 직접 추가`는 그대로 쓸 수 있다.
- 경험 목록에 시드 경험 두 개와 항목 채움 칸이 보인다.
