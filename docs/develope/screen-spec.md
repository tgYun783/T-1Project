## 1. 사용자 여정 지도

대상: 직무 관련 경험은 있지만 정리해 두지 않은 첫 구직 취준생(`statement`, `canvas.customer`).
"생각·감정" 열은 problem.yaml의 사례(E1~E4)와 통계(S#)에서만 가져왔다.

| 단계 | 사용자가 하는 일 | 생각·감정 (근거) | 막히는 곳 → 화면의 대응 | 화면 | 요구사항 |
| --- | --- | --- | --- | --- | --- |
| 0. 들어옴 | 소개를 보고 가입·로그인 | 자소서 앞에서 막막함 87.7% [S2] | 무엇을 하는 서비스인지 모름 → 한 줄과 3단계 흐름만 보여 줌 | A 소개, B 가입·로그인 | R1, C3 |
| 1. 경험 꺼내기 | 이력서를 붙여넣어 활동을 확인하고(빠진 건 직접 추가), 활동마다 AI 질문에 글로 답함(단서는 선택) | "동아리 회장·프로젝트 다 했는데 증명할 게 없네" (E2). 기록이 휘발됨 (P1) | 단서가 없음 → 단서 없이도 등록. 어디까지 말해야 할지 모름 → 항목별 상태를 실시간으로 보여 주고 스스로 멈추게 함 | D 경험 목록, E 이력서 입력, F 경험 상세 | R2, R3 |
| 2. 사실 확정 | AI가 뽑은 사실 후보를 확인·수정·삭제하고 출처를 고름 | AI가 부풀린 "15%"를 확인 없이 냄 (E4 Q2) | AI 문장을 그대로 믿음 → 후보는 "AI 제안·미확인"으로 따로 보이고, 사용자가 확정해야만 카드에 들어감 | F 경험 상세 | R4, R5, R6, C1 |
| 3. 자소서 준비 | 이미 쓴 글을 붙여넣거나, 우대사항·인재상·문항을 넣고 문항마다 카드를 골라 응답을 만듦 | 기업마다 맞춰 매번 쓰기 어려움 (E2). 마감이 몰리면 회사당 30분도 못 씀 (E4 Q1) | 어떤 경험을 쓸지 모름 → 문항마다 AI가 카드를 이유와 함께 추천, 사용자가 켜고 끔. 같은 카드 중복 → 알림 | G 붙여넣기, H 작성 시작, I 문항별 작성, J 자소서 상세 | R7, R8, R13 |
| 4. 제출 전 점검 | AI가 고른 주장 문장마다 근거 질문에 글로 답함 | "제출하기 전에 누가 '이 15%는 어디서 나온 거예요?'라고 한 번만 물어봐 줬으면" (E4 Q7). 면접관은 구체적 추가 질문으로 확인 78.6% [S22] | 어떤 문장이 위험한지 모름 → 문장별 상태와 빠진 기준(J1~J4)을 보여 줌. AI는 문장을 고치지 않음 | K 점검 | R9, R10, R11, C4 |
| 5. 고치고 보강 | 위험한 문장을 직접 고치거나, 관련 경험 대화를 이어가 카드를 보강하고 다시 만듦 → 다시 점검 | 혼자 점검하면 시간이 두 배 (E4 Q6, 가설) | 다음에 뭘 할지 모름 → 문장마다 두 바로가기. 점검에서 새로 나온 사실 → 확인 후 카드에 저장 | K → J·I 또는 F | R12, R13, C5 |

흐름:

```
A 소개 → B 가입·로그인 → C 홈(자소서 목록)
  └ 잠김(확정 카드 없음) → E 이력서 입력(활동 확인) → F 경험 상세(활동별 질문·사실 확정·카드) → C 홈(잠금 풀림)
C 홈 → G 붙여넣기 ─────────────────────┐
C 홈 → H 작성 시작 → I 문항별 작성(문항마다 ①추천 ②카드 고르기 ③생성) ─┤
                                        ▼
                                  J 자소서 상세 → K 점검
K 점검의 "추가 확인 필요·모름" 문장
  ├ 자소서에서 고치기 → J(붙여넣은 글 수정) 또는 I(그 문항 카드 다시 고르기·다시 생성)
  └ 관련 경험 대화 이어가기 → F → (보강 후) I에서 그 문항 다시 생성
  → 자소서가 바뀌면 이전 점검은 "오래됨" → K 새 점검
```

## 2. 공통

### 레이아웃·이동
- 헤더: 왼쪽 서비스 이름, 오른쪽 메뉴 `자소서`(홈) · `경험` · `로그아웃`. 로그인 전에는 `로그인` · `가입`만 보인다.
- 로그아웃은 저장된 토큰을 지우고 A로 간다(api.md 3절, 별도 API 없음).
- 단계 색(DESIGN.md 2절 "단계와 색의 짝은 한 번 정하고"): 경험 = `block-lime`(단계 1), 자소서 = `block-lilac`(단계 2), 점검 = `block-cream`(단계 3). 코럴 CTA는 소개 페이지 끝에만 한 번 쓴다(학생 답 2026-10-30 확정).
- 한 화면에 검정 주 버튼은 하나만 둔다(DESIGN.md 5절). 각 화면의 주 버튼은 아래 화면별로 적는다.

### 접근 제한 (C3)
- 토큰이 없거나 API가 `401`을 주면 B 로그인으로 보낸다. 로그인 뒤에는 원래 가려던 화면으로 돌아간다.
- 로그인한 상태로 A·B에 오면 C 홈으로 보낸다.

### 자소서 잠금 (학생 답 2026-10-30)
- 잠금 조건: 확정된 사실이 1개 이상인 경험 카드가 하나도 없음. `GET /api/experiences`의 `card`로 판단한다.
- 잠기면 C 홈의 자소서 버튼과 G·H·I·J·K 화면이 막힌다. 주소로 직접 들어와도 C 홈의 잠금 안내로 보낸다.
- 잠금 안내 문구: 경험 카드를 먼저 하나 확정해야 자소서를 쓰고 점검할 수 있다는 것과 "이력서 입력" 주 버튼.

### AI 호출 (C2)
- AI를 부르는 동작(대화 질문, 추천, 응답 생성, 문장 고르기, 문장 판정) 중에는 그 버튼을 잠그고 진행 중임을 글로 보여 준다(스트리밍 없음).
- `502 AI_UNAVAILABLE`이면 에러 문구와 "다시 시도" 버튼을 보여 준다. 사용자가 쓴 답변 글은 입력칸에 그대로 남긴다(서버는 저장하지 않았으므로 같은 요청을 다시 보낸다).

### 상태 표시 (DESIGN.md 5절 "점선 = 아직 안 된 것")
| 대상 | 값 | 표시 |
| --- | --- | --- |
| 경험 항목 상태 (R3) | `explained` 설명됨 | 흰 행 + 초록 체크 |
| | `needs_more` 추가 확인 필요 / `unknown` 모름·경험 없음 / `null` 아직 묻지 않음 | 점선 행 + 상태 글자 |
| 점검 문장 상태 (R11) | `explained` 설명됨 | 흰 행 + 초록 체크 |
| | `pending` 대기 / `in_progress` 진행 중 / `needs_more` / `unknown` | 점선 행 + 상태 글자 |
| 사실 (R5) | 후보(`ai_unverified`) | 점선 행 + "AI 제안·미확인" |

## 3. 화면

각 화면: 주소 · 목적 · 구성 · 동작(API) · 예외 · 요구사항.

### A. 소개 `/` (로그인 전)
- 목적: 무엇을 하는 서비스인지 보여 주고 가입으로 보낸다(C3).
- 구성: 서비스 한 줄(`functional_spec.summary`) → 흐름 3단계 블록(1 경험 꺼내기 lime · 2 자소서 쓰기 lilac · 3 제출 전 점검 cream, 각 한 줄 설명) → 코럴 CTA 블록(주 버튼 "가입하기", 보조 "로그인").
- 지어낸 숫자·후기는 넣지 않는다(DESIGN.md 6절).

### B. 가입 `/signup` · 로그인 `/login` (R1)
- 구성: 이메일, 비밀번호, 주 버튼("가입하기" / "로그인"), 다른 화면으로 가는 글자 링크.
- 동작: `POST /api/auth/signup` · `POST /api/auth/login` → 토큰 저장 → C 홈.
- 예외: `409 EMAIL_TAKEN` "이미 가입된 이메일", `401 INVALID_CREDENTIALS` "이메일 또는 비밀번호가 맞지 않음", `400` 칸 아래에 사유.

### C. 홈 = 자소서 목록 `/cover-letters` (R7, R8)
- 잠긴 상태: lilac 블록 대신 lime 블록 하나. 잠금 안내 + 주 버튼 "이력서 입력"(→ E). 등록한 경험이 있으면 "경험 카드 확정하러 가기" 보조 버튼(→ D).
- 열린 상태:
  - 위: 주 버튼 "새로 쓰기"(→ H), 보조 버튼 "쓴 자소서 붙여넣기"(→ G).
  - 목록(`GET /api/cover-letters`, 최근 수정순): 행마다 제목(없으면 "제목 없음"), 종류("붙여넣음" / "작성함"), 작성함이면 응답을 만든 문항 수 / 전체 문항 수, 수정 시각. 행을 누르면 J.
  - 비어 있으면 점선 행 하나로 "아직 자소서가 없어요".

### D. 경험 목록 `/experiences` (R6)
- 주 버튼: "이력서에서 활동 추가"(→ E).
- 목록(`GET /api/experiences`, 최근 수정순): 행마다 제목, 시기, 다섯 항목(상황·역할·행동·결과·의의)의 카드 채움 표시(확정 사실이 있으면 흰 칸, 없으면 점선 칸), 확인 대기 후보 수. 행을 누르면 F.
- 비어 있으면 점선 행 "아직 경험이 없어요".

### E. 이력서 입력 `/resume` (R2)
- 이력서 글을 붙여넣고 `활동 나누기`를 누르면 AI가 활동으로 나눠 `확인할 활동` 목록에 넣는다.
- 활동마다 `고치기`·`빼기`, 빠진 활동은 `활동 직접 추가`(AI 없이도 됨). 주 버튼 `경험 만들기`로 목록 전체를 확정하면 활동마다 경험이 생기고 첫 경험의 F로 간다.
- 다시 붙여넣으면 새로 나온 활동만 더한다. 경험을 따로 하나씩 만드는 화면은 없다(학생 답 2026-10-30).
- 화면 글자와 동작은 `frontend/specs/03-experiences.md`.

### F. 경험 상세 `/experiences/:id` (R2~R6, R13 보강)
lime 단계. 데스크톱은 왼쪽 대화, 오른쪽 상태·후보·카드의 두 칸.

- 위: 제목·시기(누르면 고칠 수 있음, `PATCH /api/experiences/:id`), 단서 목록(파일은 눌러서 보기 `GET .../clues/:clueId/file`, 설명 없는 파일은 "AI 질문에 안 쓰임" 표시), "단서 추가" 보조 버튼.
- 왼쪽 대화 (R3):
  - 들어왔을 때 `GET .../conversation`. 대화가 비어 있으면 자동으로 `POST .../conversation/start`를 불러 첫 질문을 띄운다.
  - AI 질문과 내 답을 줄 단위로 쌓아 보여 준다. 아래 글 입력칸 + 주 버튼 "보내기".
  - 보내기: `POST .../conversation/answers` → 답·다음 질문 추가, 오른쪽 항목 상태 갱신, 새 후보 추가.
  - 입력칸 위 안내: 오른쪽 상태를 보고 충분하면 언제든 멈춰도 된다(상한 없음, 멈춤 버튼 없음).
- 오른쪽 위 항목 상태 (R3): 상황·역할·행동·결과·의의 다섯 행을 상태 표시 규칙대로. 답할 때마다 바뀐다(`aria-live="polite"`).
- 오른쪽 가운데 사실 후보 (R4, R5, C1):
  - 후보마다 항목, 내용, "AI 제안·미확인".
  - "확정": 출처를 "내가 말함" 또는 "자료로 확인"(이 경험의 단서 선택) 중에서 고르면 `POST .../facts/:factId/confirm`. 고칠 내용이 있으면 확정 전에 내용·항목을 고친다.
  - "버리기": `DELETE .../facts/:factId`.
- 오른쪽 아래 경험 카드 (R6):
  - 다섯 항목별로 확정된 사실과 출처. 사실마다 "고치기"(`PATCH`), "지우기"(`DELETE`).
  - "직접 추가"(항목·내용·출처 → `POST .../facts`, 바로 확정).
  - 카드를 고쳐도 항목 상태는 바뀌지 않는다. 다시 대화하면 갱신된다(학생 답 2026-10-30). 이 점을 상태 영역 아래 한 줄로 적는다.
- R13 보강으로 들어온 경우(주소에 돌아갈 자소서 문항이 있을 때): 위에 "보강을 마쳤으면 문항으로 돌아가기" 보조 버튼(→ I 그 문항).

### G. 자소서 붙여넣기 `/cover-letters/paste` (R7)
- 구성: 제목(선택), 본문(필수). 주 버튼 "저장".
- 동작: `POST /api/cover-letters` → J.
- 예외: 공백만 있으면 저장하지 않고 이유를 보여 준다.

### H. 자소서 작성 시작 `/cover-letters/new` (R8)
- 구성: 제목(선택), 희망 기업의 우대사항(필수), 인재상(필수), 자소서 문항 목록(1개 이상, "문항 추가"·"빼기"). 주 버튼 "작성 시작".
- 동작: `POST /api/cover-letters/generate` → I의 첫 문항.
- 예외: 빈 칸이 있으면 칸 아래 사유.

### I. 문항별 작성 `/cover-letters/:id/items/:itemId` (R8, R13, C4)
lilac 단계. 위에 문항 진행 막대(전체 문항 칸, 응답을 만든 문항은 채움)와 문항 번호 이동. 문항은 순서대로 하나씩 진행한다.

- ① 추천: 이 문항에 추천이 없으면 들어올 때 `POST .../items/:itemId/recommendations`를 부른다. 추천 카드마다 경험 제목과 추천 이유.
- ② 카드 고르기:
  - 추천 카드와 "다른 카드"(확정 사실이 있는 나머지 경험)를 토글 버튼으로 켜고 끈다. 카드 단위로만 고른다.
  - 다른 문항에서 이미 고른 카드에는 "문항 N에 사용 중" 표시(자소서의 각 문항 `selectedExperienceIds`로 화면에서 계산). 막지 않는다.
  - 카드를 눌러 펼치면 확정된 사실을 볼 수 있다. "이 카드 보강하기" 보조 버튼은 F로 간다(돌아올 문항 정보를 가지고).
- ③ 생성: 주 버튼 "이 문항 만들기" → `PUT .../items/:itemId/experiences` → `POST .../items/:itemId/answer`.
  - 고른 카드가 없으면 버튼이 잠긴다.
  - 사용자가 고친 응답이 있으면(`answerEdited`) 먼저 "고친 내용이 새 응답으로 바뀝니다" 확인창을 띄우고, 확인하면 `confirmOverwrite: true`로 보낸다. 서버가 `409 OVERWRITE_CONFIRM_REQUIRED`를 줘도 같은 확인창을 띄운다.
- 결과: 응답 글(고칠 수 있음, "저장" 보조 버튼 → `PATCH .../items/:itemId`), 근거로 쓴 카드 목록(R13).
- 응답을 만든 뒤 "다음 문항" 보조 버튼. 마지막 문항이면 "자소서 보기"(→ J).
- AI가 응답을 알아서 다시 만들지 않는다. 다시 만들기는 사용자가 ③을 누를 때만이다(C4).

### J. 자소서 상세 `/cover-letters/:id` (R7, R13, 점검 입구)
- 붙여넣음: 본문을 바로 고칠 수 있는 편집 칸 + "저장" 보조 버튼(`PATCH /api/cover-letters/:id`, 빈 글은 저장 안 함).
- 작성함 (R13): 문항마다 문항, 응답, 근거 카드 목록(`GET /api/cover-letters/:id`의 `experiences`).
  - 문항마다 "카드 다시 고르기"(→ I 그 문항), 근거 카드마다 "보강하기"(→ F, 돌아올 문항 정보와 함께).
  - 응답을 아직 만들지 않은 문항은 점선 행 "아직 만들지 않음" + "이 문항 쓰기"(→ I).
- 점검 (cream 블록):
  - 주 버튼 "제출 전 점검 시작" → `POST /api/cover-letters/:id/checks` → K.
  - 지난 점검 목록(`GET /api/cover-letters/:id/checks`, 최신순): 만든 시각, 끝난 문장 수 / 전체, "오래됨" 표시. 누르면 K.
- 자소서를 고치면 기존 점검이 오래됨이 된다는 안내를 저장 버튼 근처에 한 줄로 적는다.

### K. 제출 전 점검 `/checks/:checkId` (R9~R12, C4)
cream 단계. 데스크톱은 왼쪽 문장 목록, 오른쪽 현재 문장의 질문·답변·후보.

- 위: 끝난 문장 수 / 전체 진행 막대와 그 아래 한 줄 설명("설명됨·추가 확인 필요·모름으로 끝난 문장 수"). 점수는 없다(R11).
- 왼쪽 문장 목록 (R9, R11): AI가 고른 주장 문장과 상태. 누르면 그 문장으로 간다.
- 오른쪽 현재 문장 (R10):
  - 들어왔을 때 진행 중인 문장이 없으면 첫 `pending` 문장의 `start`를 부른다.
  - 질문과 답을 줄 단위로 쌓아 보여 준다. 답마다 판정된 기준(J1 수치의 출처 · J2 본인의 행동 · J3 표현의 실체 · J4 단정)을 충족/빠짐으로 표시하고, 빠진 기준을 글로 적는다.
  - "남은 추가 질문 N개"(`followUpsLeft`).
  - 글 입력칸 + 주 버튼 "답하기" → `POST .../sentences/:sentenceId/answers`.
  - 문장이 끝나면 결과 상태를 보여 주고 "다음 문장" 보조 버튼(→ 다음 `pending` 문장의 `start`). 서버가 자동으로 넘기지 않는다.
- 끝난 문장이 "추가 확인 필요" 또는 "모름"일 때 (학생 답 2026-10-30):
  - "자소서에서 고치기": 붙여넣음이면 J(본문 편집), 작성함이면 I(그 문장의 문항).
  - "관련 경험 대화 이어가기": 작성함이면 그 문항의 근거 카드로(여러 개면 고르게), 붙여넣음이면 경험 목록에서 고르게 한 뒤 F.
  - AI는 문장을 고쳐 주지 않는다(C4).
- 사실 후보 (R12, C1): 점검 답에서 나온 후보마다 내용과 "AI 제안·미확인".
  - "카드에 저장": 경험(작성함이면 제안된 경험이 기본값, 붙여넣음이면 직접 선택), 항목, 출처(내가 말함 / 자료로 확인 + 그 경험의 단서)를 고르고 `POST /api/checks/:checkId/candidates/:factId/confirm`.
  - "버리기": `DELETE` 같은 경로.
- 오래된 점검(`stale: true`): 위에 "자소서가 바뀌어 이 점검은 더 진행할 수 없어요" 띠, 입력과 답하기 버튼 잠금, 주 버튼 "새 점검 시작"(→ `POST .../checks`). 기록은 그대로 볼 수 있다.
- 고를 문장이 없으면(빈 목록) "점검할 주장 문장을 찾지 못했어요"와 J로 돌아가기.

### L. 없는 주소 `*`
- "없는 페이지예요"와 홈으로 가는 버튼. API가 `404`를 준 자원(남의 것 포함)도 같은 화면을 쓴다.

## 4. 여정 ↔ 화면 ↔ 요구사항 ↔ API

| 여정 단계 | 화면 | 요구사항 | API |
| --- | --- | --- | --- |
| 0 들어옴 | A, B | R1, C3 | `auth/signup`, `auth/login`, `auth/me` |
| 1 경험 꺼내기 | D, E, F | R2, R3, R6 | `experiences`, `.../clues`, `.../conversation/start`, `.../conversation/answers` |
| 2 사실 확정 | F | R4, R5, R6, C1 | `.../facts/:factId/confirm`, `PATCH`·`DELETE .../facts/:factId`, `POST .../facts` |
| 3 자소서 준비 | C, G, H, I, J | R7, R8, R13, C4 | `cover-letters`, `cover-letters/generate`, `.../recommendations`, `.../experiences`, `.../answer`, `PATCH .../items/:itemId` |
| 4 제출 전 점검 | J, K | R9, R10, R11 | `.../checks`, `.../sentences/:sentenceId/start`, `.../answers` |
| 5 고치고 보강 | K → J·I·F | R12, R13, C5 | `.../candidates/:factId/confirm`, `PATCH /cover-letters/:id`, 경험 API |
| 공통 | 전체 | C2 | 모든 AI API의 `502` → 다시 시도 |

C5(준비 시간이 늘면 안 됨)는 가설이고 기준 값이 없다. 화면에서는 단계를 줄이는 쪽으로만 반영했다: 문항별 작성은 한 화면 안에서 추천·선택·생성을 하고, 점검은 다음 문장을 한 번에 연다.

## 5. 정하지 않은 것 (학생 답 대기)

- 단서 파일 형식·크기 제한, 비밀번호 규칙 (api.md 11절과 같음)
- 경험·자소서·단서·점검 삭제 화면 (요구사항에 없음)
- 폰 화면 세부 배치 (지금은 한 줄로 쌓기만)
