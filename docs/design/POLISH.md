# 화면 다듬기 기준 (POLISH.md)

`DESIGN.md`가 **무엇을 쓸지**(색·글꼴·모서리)를 정한다면, 이 문서는 **잘 썼는지 판정하는 기준**이에요. 화면을 고칠 때마다 1440×900 스크린샷을 찍고 아래 표를 위에서부터 확인해요. 항목은 모두 "예/아니오"로 답할 수 있게 적었어요.

> 기능·문구는 `screen-spec.md`와 `frontend/specs/`가 정해요. 이 문서로 기능을 더하거나 E2E가 찾는 글자를 바꾸지 않아요.
> 배치의 기준은 `docs/design/wireframes/`(index.html과 화면별 png)예요. 와이어프레임에 있는 화면은 그 배치를 따르고, 없는 화면은 같은 원칙으로 맞춰요.

## 1. 위계 — 3초 안에 어디를 볼지 보여야 해요

| #   | 기준                                                                                                          | 판정 방법                                              |
| --- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| H1  | 한 화면에 **주인공은 하나**예요. 가장 큰 글씨나 검정 덩어리가 두 개 이상 겨루지 않아요.                       | 스크린샷을 흐리게 봤을 때 먼저 눈이 가는 곳이 하나인가 |
| H2  | 검정 큰 블록(질문·띠)은 화면에 하나만 둬요. 카메라처럼 검정이 필요한 영역은 크기를 줄이거나 옆으로 비켜 둬요. | 검정 면적 200×200px 이상이 둘 이상인가                 |
| H3  | 글자 크기는 4단계 안에서만 써요: 제목(h2·display) / card-title 26 / 본문 15~17 / 메타 13.                     | 한 화면에 다른 크기가 5개 이상인가                     |
| H4  | 13px은 메타 정보(시각·출처·종류)에만 써요. 사용자가 읽어야 할 문장은 15px 이상이에요.                         | 질문·답변·안내 문장이 13px인가                         |
| H5  | 큰 제목(h1·h2·display)은 화면에 하나예요. 섹션 이름(대화, 항목 상태, 확인할 사실 등)은 13~17px 이름표로 써요.  | 40px 넘는 글자 줄이 둘 이상인가                       |
| H6  | 바탕은 흰색(`canvas`)이에요. 섹션은 흰 카드 + 얇은 선(검정 12%)으로 나누고, 화면 전체를 단계 색 덩어리로 채우지 않아요. | 단계 색 면적이 화면의 30%를 넘는가                     |

## 2. 의미 — 같은 모양은 같은 뜻이에요

| #   | 기준                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------- |
| M1  | **점선 = 아직 비어 있는 것**에만 써요. "지금 말하지 않는 면접관"처럼 비어 있지 않은 것에는 쓰지 않아요. |
| M2  | 단계 색은 경험(이력서·활동 질문)=lime, 자소서=lilac, 제출 전 점검=cream, 마지막 CTA=coral로 모든 화면에서 같아요. 단계 색은 **표시**(단계 칩, 선택된 행, 강조 표시)에만 써요. |
| M3  | 검정 주 버튼은 화면(또는 카드)마다 하나예요. 나머지는 흰 알약이에요.                                    |
| M4  | 상태 표시(설명됨/추가 확인 필요/모름·경험 없음, 대기/진행 중)는 글자와 모양을 같이 바꿔요. 색만으로 구분하지 않아요. |
| M5  | 같은 말을 반복하는 점선 행을 여러 개 두지 않아요. 항목 상태처럼 여러 개를 한 번에 보일 때는 진행 막대 + 칩으로 묶어요. |

## 3. 디테일 — "만든 사람이 신경 썼다"가 보이는 곳

| #   | 기준                                                                                                      |
| --- | --------------------------------------------------------------------------------------------------------- |
| D1  | 한글 제목 자간은 **-0.02em ~ -0.03em**이에요. -0.045em은 Inter(영문·숫자)일 때만 써요.                    |
| D2  | 모든 버튼·링크·선택 행에 **hover · active · focus-visible** 모양이 있어요. 바뀌는 데 150ms 전환이 있어요. |
| D3  | 눌러서 되돌릴 수 없는 버튼(승인·면접 종료)은 누르는 중에 문구가 바뀌어요("반영하는 중").                  |
| D4  | 숫자(타이머, 질문 번호, 개수)는 `tabular-nums`라서 바뀌어도 폭이 흔들리지 않아요.                         |
| D5  | 줄 길이는 본문 기준 한 줄 40~60자(최대 640px)예요. 넓은 화면에서 문장이 끝없이 늘어나지 않아요.           |
| D6  | 간격은 4의 배수만 써요. 같은 묶음 안 8~12px, 묶음 사이 16~24px, 구역 사이 48px 이상이에요.                |

## 4. 상태 — 빈 화면이 한 순간도 없어요

| #   | 기준                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------- |
| S1  | 불러오는 중에는 '불러오는 중' 글자와 함께 **나올 내용 자리만큼 스켈레톤**을 보여 줘요. 흰 화면에 한 줄만 두지 않아요. |
| S2  | 비어 있음 = 점선 상자 + 한 줄 안내 + 이동 버튼이에요.                                                                 |
| S3  | 기다리는 상태(질문 준비, 전사, 결과 정리)에는 움직이는 표시가 하나 있어요. 단, `prefers-reduced-motion`이면 멈춰요.   |

## 5. 데모 화면 우선순위

발표는 **소개 → 이력서 입력 → 활동별 질문(경험 상세) → 자소서와 근거 카드 → 제출 전 점검** 순서로 보여 줘요. 이 다섯 화면은 위 기준을 모두 통과해야 하고, 나머지 화면은 1·2절만 통과하면 돼요.

## 확인 순서

1. `cd frontend && npm run shot -- <화면> --tag before` 로 고치기 전 1440×900 스크린샷을 찍어요(화면 이름: intro, login, home, resume, experiences, experience, paste, new, letter, write, check). 결과는 `frontend/shots/before/<화면>.png`.
2. 스크린샷과 `docs/design/wireframes/<화면>.png`를 열어 보고, 위 표를 H → M → D → S 순서로 확인해 걸린 항목 번호를 적어요.
3. 고친 뒤 `npm run shot -- <화면> --tag after` 로 다시 찍어 와이어프레임·before와 비교해요.
4. `npm run check`(타입·린트·포맷·테스트·빌드)가 통과해야 끝이에요.
