# 범위 확인사항 (2026-10-30, 미해결)

## 이번에 정한 것 (학생 답 2026-10-30)

- 해법(`solution_paths`)은 기존 3개 구조와 이름을 유지한다.
  - 경로 1 경험 스캐너: `chosen`
  - 경로 2 맞춤형 자소서 빌더: `chosen`. **제출 전 문장 점검은 새 해법이 아니라 경로 2의 "작성한 내용의 근거와 설명 가능 여부를 확인하는 단계"**로 본다(`functional_spec` R9~R12).
  - 경로 3 내 경험 기반 음성 모의면접: **`deferred`(보류)**. 기존 설계는 보존한다.
- `features`와 `functional_spec`은 **고정**한다. 번호 변경·항목 이동·삭제를 하지 않는다.
- 새 기능이나 새 해법은 추가하지 않는다.

## 남은 불일치 (모두 미해결)

기능 명세를 고정했기 때문에 아래가 남는다. 해결된 것으로 표시하지 않는다.

### 1. `features`(F1~F10)와 `functional_spec`(R1~R13)이 다른 범위를 말한다

- `functional_spec`의 핵심(R2~R6 경험 발굴·경험 카드, R8 경험 기반 작성, R9~R12 제출 전 점검, R13 근거 카드)에 해당하는 항목이 `features`에 없다.
- 대회 대시보드와 안내서는 `features`(id·name·input·output·done)를 기능 명세로 읽는다.
- `features`에는 `functional_spec`에 없는 F2 이력서 템플릿 입력, F3 맞춤형 자기소개서 만들기(템플릿 선택)가 있다.
- F5~F10은 모의면접 기능(경로 3, 보류)인데 `features`에는 상태 칸이 없어 만들 기능처럼 보인다. F10 주석은 "solution_paths 3번에 속하는 기능"이라고 적혀 있다.
- `functional_spec` 머리 주석은 "F1~F10은 보류된 모의면접 항목에만 근거로 쓴다"인데, F1(회원가입)·F4(자소서 등록)은 모의면접이 아니고 R1·R7과 같은 내용이다.

### 2. `insight.design_decision`이 보류된 경로 3을 포함한다

- "3단계(경험 스캐너 → 맞춤형 자소서 빌더 → 내 경험 기반 음성 모의면접)"로 적혀 있다.

### 3. 현재 대안의 `why_ours`가 면접 기능을 약속한다

- A1: "다른 각도의 질문으로 다시 연습하는 흐름"
- A2: "그 사실을 면접 질문·답변·피드백·재연습에 연결한다"
- 둘 다 보류된 경로 3(F5~F10)에 기대는 설명이다.

### 4. 흐름(`docs/scenarios.yaml`)과 E2E

- S1~S6 중 S2(이력서 템플릿, F2), S3(템플릿 자소서, F3), S5·S6(모의면접, 보류)이 현재 범위 밖이다.
- 선택한 경로 1(경험 대화·사실 확정·경험 카드)과 경로 2의 확인 단계(주장 문장 점검·근거 질문·사실 저장)를 끝까지 해내는 흐름이 없다. 안내서는 `chosen` 경로마다 그 경로를 끝까지 해내는 흐름을 요구한다.
- 저장소에 `e2e/` 폴더(흐름별 spec)가 아직 없다.
- 흐름은 `features`를 바탕으로 쓰는데 1번 불일치 때문에 기준을 정하기 어렵다.
