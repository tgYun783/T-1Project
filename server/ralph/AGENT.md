# AGENT.md — 백엔드 루프 표지판 (규칙만, 상태 보고 금지)

## 대회 규칙 (03-delivery.md)
- 환경변수 이름 고정: `RELEASE_ID`, `DATABASE_URL`, `SEED_USER_EMAIL`, `SEED_USER_PASSWORD`, `AI_GATEWAY_API_KEY`. 다른 이름·파일에서 읽지 않는다.
- `GET /__health`: 인증·리다이렉트 없이 200, `{"releaseId": RELEASE_ID}`, `Cache-Control: no-store`. 비밀값 노출 금지.
- 코드·설정에 `http://localhost:3000` 같은 절대 주소 금지. 상대 경로.
- 없는 경로는 404(500 아님). 오류 응답에 스택·비밀값을 넣지 않는다.
- AI 키는 서버만 `AI_GATEWAY_API_KEY`로 읽고, 키가 비어도 앱은 기동한다. 재시도 상한을 둔다.
- **AI 비용은 팀 전체 $10.** 테스트·검증에서 실제 Gateway를 호출하지 않는다(AiModule은 항상 mock). `.env`를 만들거나 키를 넣지 않는다. 실제 호출 확인은 사람이 단계마다 1회만 한다.
- compose: 서비스 `app` + `"3000:3000"` 유지, 다른 서비스에 ports·container_name 금지, `env_file` 금지, 시드 값은 그대로 적는다(`${}` 금지).
- 빌드는 Dockerfile에서 끝내고 시작 명령은 서버 실행(+시드)만. 기동 후 2분 안 `/__health` 200.
- `node_modules/`·`dist/`·`.env`를 커밋하지 않는다.

## 코드 규칙
- 구현 전에 `server/src`를 검색해 이미 있는지 확인한다. 있다고도 없다고도 가정하지 않는다.
- 임시 구현·빈 함수·TODO로 넘어가지 않는다. 고정 예시 결과를 돌려주는 구현 금지.
- TDD: 실패하는 테스트 → 구현 → `npm run check` → 통과할 때까지. 테스트와 구현에 "왜 중요한지" 주석 한 줄.
- 기존 `*.spec.ts`는 지우거나 약화하지 않는다. 틀렸다고 보면 review에 이유를 쓴다.
- 소유자 검사는 서버에서(세션 사용자 ≠ 자원 소유자 → 404).
- 모델 이름·한도 숫자는 설정 파일/환경변수로, 코드에 박지 않는다.

## 루프 규칙
- 한 반복에 주장 하나. 다른 주장의 일은 하지 않는다.
- verify는 코드를 고치지 않는다. fix는 검색하지 않고 제안만 반영한다. confirm은 diff만 본다.
- 막히면 산출물 첫 줄에 `FAIL`/`REJECT`와 함께 사유를 쓴다. 완료 선언 문구는 쓰지 않는다(판정은 check.mjs).

## 표지판 (실패에서 배운 규칙 — 한 줄씩 추가)
- (2026-10-29) npm 명령은 저장소 루트에서 `npm --prefix server run check`처럼 `--prefix server` 형태로 쓴다. 다른 형태는 권한 규칙에 막힌다.
- (2026-10-29) verify·confirm의 판정은 파일 첫 줄(`VERDICT:`/`CONFIRM:`)로만 읽힌다. 출력창에 쓴 판정은 버려진다.
- (2026-10-29) YAML 값이 따옴표로 시작하면 파서 오류. 줄 전체를 큰따옴표로 감싼다. (2026-10-30 재발 2회: 편집 뒤 반드시 파서로 확인)
